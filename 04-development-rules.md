# Development and AI Rules

1. Read master plan, architecture, data model and assigned section script before coding.
2. One task, one short-lived feature branch; use PRs, not direct pushes to main.
3. No unapproved changes to schema, authorization, API contracts or finance rules.
4. Keep each task scoped; propose separate tickets for unrelated changes.
5. Write tests for validation, failures, permission denial and main success paths.
6. Never paste production secrets or customer data into AI tools.
7. Report files changed, migrations, test commands, outcomes and remaining risks.
8. QA and owner sign-off are required before marking Done.
9. Keep documentation synchronized with accepted implementation.
10. Do not let AI autonomously deploy or migrate production systems.
